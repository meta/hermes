Constructing a typed class through an untyped callee (`new C()` with
`C: any`) goes through the generic `new` path: `CreateThisInst`
allocates a plain object, and the typed constructor then stores the
class's fields into layout slots of that object instead of named
properties. The typed `new` path (`genNewExpr` with a
`ClassConstructorType` callee) allocates the class's typed layout, or a
fast array for `Array<T>` and classes deriving from it.

    class Bar { x: number = 1; get(): number { return this.x; } }
    const C: any = Bar;
    const b: any = new C();
    print(b.x, b.get());   // prints "undefined 1"

    class Foo extends Array<number> { size(): number { return this.length; } }
    const F: any = Foo;
    const f: any = new F();
    print(f.size());       // a plain object, not a fast array

Predates the IR type system v2 stack; found by an external (Codex)
review of "Allocate fast arrays for new Array<T>()". A fix needs the
dynamic construction path to know the class's allocation kind (typed
layout or fast array), e.g. through `CreateThis` or by having the typed
constructor allocate when called with a generic `this`: a runtime and
IRGen design change.
