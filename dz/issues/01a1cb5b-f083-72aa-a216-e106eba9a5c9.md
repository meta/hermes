Typed mode has no promise or generator types. A call to a typed async
function or generator therefore gets an interim type: `mixed` in Flow and
`object` in the IR. Add real types, so that:

- a call to `async function f(): T` is `Promise<T>`;
- `await` of a `Promise<T>` is `T` (today every `await` is `any`, with the
  warning "ft: await expression not supported, assuming 'any'", the
  `AwaitExpressionNode` visitor in `lib/Sema/FlowChecker-expr.cpp`);
- a call to a generator is a generator of its yield, return and next
  types (today `yield` is typed `mixed`, the `YieldExpressionNode`
  visitor, and the call is `mixed`).

Until then, inside a typed async function, `return af()` for another
typed async `af` is a compile error (`mixed` into the annotated type);
`return await af()` works, since `await` is `any`, and
`return (af(): any)` compiles but fails the checked cast at run time.

The annotation stays the return type of the signature (the promise's
value type, the generator's return value): it types the function's
`return` statements, and Flow function assignability (`canAFlowIntoB`)
compares it and requires equal async and generator flags. The IR
`Function` type records it too (`lowerTypedFunction`). Deep structural
subtyping (D10, `doc/plans/ir-type/phase3-5-design.md`) must keep
treating it as the annotation.

Interim types and the code that sets them, to replace in one go:

- Flow, `mixed`: `FlowContext::getCallResultType`
  (`include/hermes/Sema/FlowContext.h`), based on
  `TypedFunctionType::callWrapsReturnType`. It is used at the four sites
  in `lib/Sema/FlowChecker-expr.cpp` that type a typed call: static
  `SH_call` dispatch (unreachable for now, async and generator methods
  are rejected with "ft: async/generator methods unsupported"), the main
  call path, `$SHBuiltin.call`, and `fn.call(...)`.
- IR, `object`: `ESTreeIRGen::emitCall` (`lib/IRGen/ESTreeIRGen-expr.cpp`)
  types the `CallInst` `object` when `callWrapsReturnType()` holds. The
  `$SHBuiltin.call` and `fn.call` lowerings leave the `CallInst` `any`.
- The comments that describe the interim types: `TypedFunctionType` and
  `getCallResultType` (`FlowContext.h`), `Function::functionType_`
  (`include/hermes/IR/IR.h`), `TypeContext::createFunction`
  (`include/hermes/IR/TypeContext.h`), and the note after D10 in
  `phase3-5-design.md`.

Test: `test/shermes/typed-async-generator-call.js` checks the interim
types and must change with them.
