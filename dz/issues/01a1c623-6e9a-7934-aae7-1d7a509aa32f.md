FlowChecker types a call to a typed async or generator function with the
annotated return type, not a promise or generator object, and IRGen trusts
it (the typed `CallInst` has the annotated type, no check).

    async function af(): number { return 1; }
    const r: number = af();
    print(typeof r);

`shermes -typed -O0 -exec` prints `object` (a promise in a `number`
binding); at `-O`, `typeof` is folded and it prints `number`. Also on the
base master commit (3f124a87e23c), before the IR type system v2 stack.

The generator form fails IR verification at `-O`:

    function *g(): number { yield 1; return 2; }
    function use(): void { const it = g(); print(typeof it); }
    use();

`shermes -typed -O -verify-ir -exec`: "CallInst: NoType instruction has
output" after TypeInference.

The fix belongs in FlowChecker: the call's type should be the promise or
generator type (or the call should be treated as untyped).
