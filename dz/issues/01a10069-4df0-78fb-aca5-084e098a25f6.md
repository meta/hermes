The checked-in wasm2c blobs under `API/hermes_sandbox/external/`
(`hermes_sandbox_impl_{dbg,opt}_compiled*`) were built from
the VM before the GCScope-to-Locals migration, so they still contain the
old VM, including `markGCScopes` (only the dbg blob; the opt blobs do
not). Nothing is functionally broken: they are self-contained,
`hermesSandboxRuntime` builds, and APITests (which link it) pass.
They should be regenerated so the sandbox ships the migrated VM.

The toolchain was not available when the migration landed (no emcc/emsdk
or wasm2c; only wasm-ld and llvm brews).

Command (see API/hermes_sandbox/README.md, which pins emsdk 3.1.39 and
wasm2c 1.0.33):

1. Build `hermesc` for the host (`build_host`).
2. Configure `build_wasm_dbg` and `build_wasm_opt` with the Emscripten
   toolchain file and the flags in the README.
3. `cmake --build build_wasm_{dbg,opt} --target hermesSandboxImpl`
4. `wasm2c build_wasm_{dbg,opt}/API/hermes_sandbox/hermesSandboxImpl.wasm
   -n hermes --num-outputs 8 -o
   API/hermes_sandbox/external/hermes_sandbox_impl_{dbg,opt}_compiled.c`
5. `python3 API/hermes_sandbox/shorten_names.py
   API/hermes_sandbox/external/hermes_sandbox_impl_{dbg,opt}_compiled*`,
   and check the imports with `wasm-objdump -x -j Import` (see the
   README). Follow the `regenerate-sandbox` skill for the output checks.

Then run the tests in
`.claude/skills/regenerate-sandbox/references/testing.md`.
