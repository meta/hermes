GetByVal compiles to a bare call to _sh_ljs_get_by_val_rjs (x86-64
Emitter::getByVal, JitEmitter-property.cpp); the dense-array and
typed-array fast paths live in C++ inside the helper
(tryFastGetComputedMayAlloc). Every read pays the call, the object
check, the f64->u32 key conversion, and vmisa dispatch in C++.

An inline tier mirroring emitPutByValFastArrayTier would cover the
dense JSArray read (kind check, fast-flags check, key-is-uint32,
beginIndex/elemCount range check, element load, empty-slot decline)
and could extend to typed arrays (kind range check, attached + bounds,
typed element load + conversion to HermesValue).

Unlike the PutById tier this needs no property cache and no
recompilation trigger for the JSArray case; a typed-array tier that
specializes on the observed element kind would be a natural consumer
of per-version feedback records (JitVersionData::consumerRecords).

See also the PutByVal typed-array counterpart issue.
