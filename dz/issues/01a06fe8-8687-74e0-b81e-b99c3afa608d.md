lib/VM/JIT/JitCompiler.cpp is the arch-independent compiler driver,
compiled once per binary inside namespace HERMESVM_JIT_ARCH_NS (arm64
or x86_64, selected by JitCurArch.h based on host architecture), and is
listed unconditionally in lib/VM/CMakeLists.txt whenever
HERMESVM_ALLOW_JIT is on. Task 3 (JIT: report ById sites left cold by a
compile, a49199b35) added `em_.coldByIdSites_` reads in
JitCompiler.cpp's compileCodeBlockImpl() (currently around lines
399/442/443), but `coldByIdSites_` is only declared on
`x86_64::Emitter` (lib/VM/JIT/x86-64/JitEmitter.h:569); there is no
matching member on `arm64::Emitter`.

This breaks any arm64 build with the JIT enabled:

    /home/.../lib/VM/JIT/JitCompiler.cpp:399:11: error: no member named
    'coldByIdSites_' in 'hermes::vm::arm64::Emitter'

Reproduced 2026-09-05 on the cmake-build-arm64 cross tree
(`cmake --build cmake-build-arm64 --target hermes`), and confirmed
pre-existing (not a Task 4 regression) by compiling HEAD~1's
lib/VM/JIT/JitCompiler.cpp standalone against the same arm64 target:
identical 4 errors, same lines.

Fix is presumably to add a `coldByIdSites_` counter (and its increment
sites) to `arm64::Emitter` mirroring the x86-64 one, or to move the
field to a shared/arch-neutral location if one exists for exactly this
purpose. Not investigated further; out of scope for the task that found
it (JIT recompilation, Task 4), which only touches the arch-neutral
JitCompiler.cpp/JitHandlers.cpp and the two arch JIT.h headers.

    Fixed by mirroring a dormant coldByIdSites_ member into
    arm64::Emitter (lib/VM/JIT/arm64/JitEmitter.h), same doc comment as
    x86-64 plus a note that the arm64 emitter does not yet report cold
    sites, so it stays 0 and the recompilation mechanism is dormant on
    arm64 until arm64 gains its own cold-site reporting. No arm64 .cpp
    changes; the member is never incremented there.

    Verified: cmake-build-arm64 now produces a complete hermes binary
    (cmake --build cmake-build-arm64 --target hermes, exit 0, full link).

    Follow-on: running the arm64 jit lit suite on that tree surfaced a
    related but distinct defect -- 7 pre-existing arch-neutral tests
    (construct.js, consts.js, envops.js, load-parent-notraps.js, misc.js,
    new-object.js, objops.js) fail because they pin a "JIT cold ById
    sites: N" line that this dormant field guarantees never prints on
    arm64. Filed separately (that line's absence is expected/dormant
    behavior, not a compile break) rather than reopening this one.
