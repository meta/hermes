On the React benchmarks most PutById stores that leave JIT code hit the
site's write cache in `_jit_put_by_id` (lib/VM/JIT/JitHandlers.cpp):
the store is to an existing property of a class the cache already
holds, the same case the inline tier serves. On pixel-grid-small
13.13M of the 13.48M calls to the helper are such hits, and on
pixel-grid 73.89M of 77.65M. `_jit_put_by_id` takes 3.3% of
pixel-grid-small's samples with what it calls, 2.2% in itself.

Measured at cdd19983b, 2026-11-19: Release, HV64, `-Xjit`, from
bytecode, one run each, with counters added to a scratch copy (the
helper's outcome, and the slow path's per (class, name) repeats); the
profile is of the build without counters, perf `--call-graph dwarf`.

| bench | helper calls | write-cache hits | add-cache hits | slow path |
|---|---|---|---|---|
| pixel-grid-small | 13477335 | 13133248 | 343878 | 209 |
| pixel-grid | 77654099 | 73886975 | 3767018 | 106 |
| draw | 977078 | 905521 | 71321 | 236 |
| relay-feed | 2211309 | 118812 | 2092425 | 72 |
| RayTrace | 65320895 | 334864 | 64405277 | 580754 |
| DeltaBlue | 11068224 | 1575780 | 9013353 | 479091 |
| TypeScript | 24575473 | 6438910 | 15561955 | 2574608 |
| Earley-Boyer | 84691076 | 66 | 70959306 | 13731704 |

The add-cache hits are dz 01a185d0-5d7c (an add never runs inline);
relay-feed's helper calls are 95% of that kind.

## Why the inline tier declines

Not yet known. `putByIdImpl` (lib/VM/JIT/x86-64/JitEmitter-property.cpp)
emits the inline tier only when the site's write cache names a class at
compile time, and the tier tests that one class. A hit in the helper is
therefore one of:
- a site compiled while its write cache was empty, and never
  recompiled with the cache warm;
- a site whose class at compile time is not the one it now sees, for
  example a site that sees two classes, one inline and the other in the
  helper's cache;
- a site whose class got no lazy ID (`initHCLazyIDMayAlloc` returned
  0);
- a site whose inline tier matched the class but whose barrier
  predicate (`emitSafeStoreOrSlow`) declined: an old-generation target
  while the marking barriers are on or a compaction is in progress, or
  a jumbo segment (dz 01a18b30-a55b).
Count the hits per site and record, per site, whether the body has an
inline tier and for which class, and how many hits arrive while marking
or a compaction is active, before choosing a fix. The fix for the
first case is in the recompile policy; for the second, a second class
in the inline tier.

## Not the lever: a (class, name) cache behind the PutById slow path

`ComputedPropertyCache` could serve the PutById misses that reach
`Interpreter::putByIdSlowPath_RJS`, both stores and adds. Measured
against the same runs, it would save almost nothing:

| bench | slow-path calls | existing-property stores / adds / other | repeats of a (class, name) |
|---|---|---|---|
| pixel-grid-small | 709 | 437 / 259 / 13 | 433 |
| pixel-grid | 608 | 336 / 259 / 13 | 331 |
| draw | 708 | 435 / 259 / 14 | 425 |
| relay-feed | 741 | 346 / 376 / 19 | 357 |
| RayTrace | 580957 | 70642 / 510296 / 19 | 580776 |
| DeltaBlue | 479338 | 90 / 479236 / 12 | 479125 |
| TypeScript | 2582942 | 2048139 / 448316 / 86487 | 2579124 |
| Earley-Boyer | 13732333 | 13732190 / 129 / 14 | 13 |

The slow-path count includes the interpreter's misses, so it is a little
above the helper's. A repeat is a slow-path call whose (class, name)
pair an earlier call already had, an upper bound on the hits of a table
that never evicts; a store or add to a dictionary never counts. The
classes were keyed by address, so a class the GC moved counts as new.

- React reaches the slow path about 700 times per run, the same warm-up
  misses whatever the run's length.
- On RayTrace, DeltaBlue and TypeScript the misses repeat, but the slow
  path and what it calls take at most about 1.5% of TypeScript's samples,
  and under 1% of DeltaBlue's and RayTrace's; a cache would remove part
  of that.
- Earley-Boyer's 13.7M misses are stores to objects in dictionary mode,
  which the cache does not serve.

The counting patch, its scripts and the raw output were in
/tmp/claude-1000/react-bench/cpc/poly (patch.py, count.sh, prof.sh,
out/).
