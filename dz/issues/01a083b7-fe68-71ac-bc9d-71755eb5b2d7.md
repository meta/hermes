A function whose ByVal site sees only fast JSArray stores never
declines: no declines, no counter, no considerRecompile, no recompile.
The flag is shed only by re-emission on evidence, re-emission requires
a recompile, and a pure-JSArray function has nothing to trigger one --
so it executes the instrumented version-1 body (movabs + mov byte
[r11],1 per successful inline store) for its entire lifetime. The
spec's cost claim "shed entirely at the first recompile" is vacuous
for exactly the most common case, which never has a first recompile.

Measured (per-kind fill benchmark, base = pre-feature, head = with
feature, -Xjit=force):

    dense Array control  HV64 47->49 ms (0.96x)   HV32 52->53 (0.98x)

Proposed fix -- eliminate the flag instead of cheapening it: change
the tier-selection rule to "never drop a prior JSArray tier on
typed-array evidence; drop it only on otherSeen-only evidence". Then:

- pure JSArray: v1 tier, no flag, no recompile -- 1.00x restored;
- pure TA: the recompile emits the TA tier first with the vestigial
  JSArray tier chained behind its kind miss -- zero hot-path cost
  (the TA path never reaches it), ~30 instructions of code size;
- mixed: both tiers at the first recompile, budget 1 converges, and
  nothing needed the flag to learn it;
- plain object: otherSeen-only still drops the tier.

This deletes the flag emission, the emitter plumbing, and the
"prior-based in any version" instrumentation rule, and obsoletes the
delayed-first-execution machinery. The only loss is the ability to
shed the JSArray tier at a pure-TA site, which costs code size and
nothing else. (This is the conservative keep-both selection the
original design discussion rejected in favor of full shape tracking;
the benchmark is the argument for reversing that.)

Rejected alternatives: branch-over-flag (load+test+branch beats a
blind store only if the line is contended, and it is not); shedding
via a new "flag-set" progress source (no trigger exists -- the site
never calls a helper); sampling the store (branchy, worse).

Requires a spec amendment (Tier selection at recompile) and rework of
recompile-taval-delayed-site.js / -mono-jsarray.js, whose pins exist
to test the flag. Related: 01a0828c (follow-up coverage), and the
hopeless-site recording-tax issue filed alongside this one.
