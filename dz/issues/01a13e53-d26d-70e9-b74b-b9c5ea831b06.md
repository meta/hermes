`addCacheShape` and `preparePolyChain` (about 60 lines: fold the live cache
entry into the site record, assign lazy JIT IDs, mark entries emitted or
unemittable, build and partition `poly_`) are identical in
`lib/VM/JIT/x86-64/JitEmitter-property.cpp` and
`lib/VM/JIT/arm64/JitEmitter-property.cpp`. They touch only the shared
`JitByIdSiteRecord`, the runtime and `initHCLazyIDMayAlloc`, no
assembler types, so the two copies can drift: a fix to the monotone
carry-forward, the GC-safepoint re-read of the weak roots, or the entry
cap would have to be made twice.

Hoisting needs a home that both emitters include and that can reach
`JITContext`/the site record without pulling in either backend's
assembler headers, which neither emitter file has today.
