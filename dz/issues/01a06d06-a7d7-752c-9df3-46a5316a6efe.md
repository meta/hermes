The recompilation mechanism (spec:
doc/superpowers/specs/2026-09-04-jit-recompilation-design.md) retires
the previous body of a function when a new version is installed. In v1
retired bodies are never freed: JITContext::Impl owns all emitted code
until the context dies (which was already true with one body per
function), and the per-function recompile budget bounds the growth.

This issue is the follow-up: actually reclaim retired bodies. The
constraint is that a retired body may still be executing — return
addresses on the native stack can point into it — so it can only be
freed once no frame references it.

Sketch discussed and deferred: keep retired versions on a list; at a
quiescent point (a GC is a natural host), conservatively scan the
native stack(s) for return addresses falling inside the JIT code
region and free the retired versions nobody references. Care needed
for fiber stacks (Boost.Context) — every live stack must be scanned,
not just the current one. This is subtle, rarely-exercised machinery;
it stayed out of v1 deliberately so the mechanism could land without
it. Do not build it until retired-code memory is measured to matter
in a real workload.
