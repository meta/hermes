The polymorphic GetById tier (spec doc/superpowers/specs/2026-10-14-jit-getbyid-polymorphic-design.md) only handles own properties and the immediate prototype, because it harvests the interpreter read cache, which caches nothing deeper. Octane DeltaBlue's method reads resolve two or more prototypes up (class hierarchies), so those sites record nothing and demote (43 demotions); DeltaBlue moved only +1-5%, within noise, while the profile (dz 01a13c62) showed ~30% of its time in getById misses. Covering deeper chains needs a validity scheme for each prototype on the path (class IDs per level, or a prototype-chain epoch) and cannot come from the one-level read cache.

    Measured at e5c158faa (Release, -Xjit, from .hbc; instrumented slow-path counters in getByIdWithReceiver_RJS):

    - DeltaBlue: 31.8M slow GetById calls from 55 sites. Depth: own 0%, proto 1 1.3%, proto 2 95.7%, proto 3 3.0%. No accessors, dictionaries or primitive receivers. 99.98% go through the demoted plain helper and the C++ read cache hits 0.6%, so nearly every call walks the chain. At most 3 receiver classes per site. All top sites are method loads (`this.input()`/`this.output()` in EqualityConstraint.prototype.execute are 63%); the depth comes from `inheritsFrom` inserting an Inheriter instance into every chain.
    - RayTrace: only 6.2% at depth 2. 81.6% of misses are one site, `this.initialize` in Class.create: one receiver class, 13 holder classes.
    - TypeScript: 74% of misses have a string receiver (charCodeAt 44%, length 27%); depth 2+ is about 11% of object-receiver misses.
    - parentCacheEpoch_ never changed between first and last miss in any of the three.

    Approaches considered:
    - A: per-level class checks (load parent, load class, compare lazy ID, per level). Local invalidation, cost grows with depth, one more class per level per entry.
    - B: receiver class + parentCacheEpoch_ compare, then load from the recorded holder. Constant cost at any depth; flags chain objects with isCachedUsingEpoch; the JIT records must be invalidated on epoch wraparound; dictionary objects on the path are excluded, as in tryCacheAddProperty.

    Decision: B, designed for the world after PR facebook/hermes#1939 (prototype moved into HiddenClass::objectParent_), where the receiver class fixes the prototype and the check is two compares. Without that PR B would also need a compare of the receiver's parent pointer. Blocked until #1939 lands; the GitHub export (avp:export-D84654981, ef1faecf3, 2026-03-16) is far behind and conflicts with this branch. After it lands: isCachedUsingEpoch becomes a class flag, so flagging a prototype at record time transitions its class once and invalidates existing entries for it once.
