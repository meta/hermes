The x86-64 backend gained an inline write-barrier predicate
(Emitter::emitSafeStoreOrSlow) and inline PutById / PutByVal tiers, in
all heap-value modes (commits a6f04de64, 01394da2b, 3febfffb5,
faa6c94b3; spec doc/superpowers/specs/2026-08-27-jit-inline-property-
writes.md; doc/JIT.md "Inline write barrier (x86-64)"). Measured on
x86-64: pixel-grid +5% (HV64) / +3.5% (HV32), Richards +16.6% / +8.5%.
arm64 still emits helper calls for every property write and keeps the
"TODO: Fix this once we can inline write barriers" comment in
JitEmitter-object.cpp. The design is architecture-independent; porting
it is mechanical but ends arm64's byte-identical relationship with the
export base a second time (the first was e9059de85), so it needs the
arm64 dump-baseline workflow (doc/JITTesting.md) and the same gates.
