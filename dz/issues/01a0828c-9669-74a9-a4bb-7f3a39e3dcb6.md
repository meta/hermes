Final whole-branch review of the PutByVal shape-feedback and
typed-array store tier work (dz 01a07f0a-def8, see
doc/superpowers/specs/2026-09-08-jit-putbyval-typed-array-design.md)
identified four deferred coverage gaps, none blocking, all worth
closing in a follow-up:

1. No CI configuration exercises
   HERMES_JIT_INLINE_SAFE_STORE == 0 (MallocGC + JIT) — the codepath
   where the JSArray tier is unavailable and only the typed-array
   tier can be emitted.

2. A poisoned-TA site (a second, different typed-array kind
   observed) that later also sees JSArray traffic de-specializes at
   its next recompile once the budget allows a further version
   (budget >= 2). This is correct per the design's tier-selection
   rules, but it is untested and uncommented in the code.

3. No emitted-code pin (lit test with -Xdump-jitcode or similar)
   for the specific symbol `_jit_put_by_val_strict` — only the loose
   variant appears to be pinned at the call-site level.

4. No test for the otherSeen recording path when an unsupported
   typed-array kind (Uint8Clamped, Float16, or a BigInt kind) is the
   target — i.e. that these permanently decline and record as
   otherSeen rather than ever being (mis)specialized.

      scope of the PutByVal commit itself, but the same fix applies.

    - Expanding item 3 above: no lit test proves an inline tier actually
      EXECUTES rather than merely being emitted. Every existing test can
      only observe emitted code (via -Xdump-jitcode) or interpreter-
      equivalent output, because helper/tier behavioral equivalence is
      the design invariant -- an output test cannot distinguish "the
      tier ran" from "the helper ran and produced the same result". The
      perf run is currently the only evidence a tier is ever taken. A
      helper-decline JitCounter surfaced to tests (incremented whenever
      a site falls through an inline tier to the helper, or conversely
      when the inline tier completes the store) would close this gap for
      every inline tier kind, not just PutByVal's.
